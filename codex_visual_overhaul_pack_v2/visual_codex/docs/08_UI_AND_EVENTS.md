# 08 — UI et événements

## Philosophie

UI minimale, lisible, cohérente avec la BD/cartoon.

Ne pas transformer le jeu en interface de gestion.

## HUD principal

- argent en haut gauche ;
- revenu si encore présent dans la version actuelle ;
- J-XXX en haut centre ;
- Pause / Plein écran en haut droite si desktop ;
- sur mobile, adapter aux contrôles existants.

Créer des cadres illustrés simples, pas massifs.

## Décision stratégique QG

L'avis "Choisissez votre type de campagne" peut être illustré mais doit :
- rester temporaire ou peu intrusif ;
- ne pas cacher la moitié de l'écran ;
- respecter la logique existante.

## Cartes événements

État initial :
- apparition en haut-centre ;
- carte plus grande ;
- icône famille ;
- titre court ;
- sous-titre.

Puis :
- glisse/rétrécit vers haut-droite ;
- pile verticale ;
- plus ancien en haut ;
- actif uniquement.

Créer un petit set d'icônes :
- meeting de crise ;
- choc d'opinion ;
- candidat fragilisé ;
- piège médiatique ;
- débat ;
- crise de financement ;
- fermeture bâtiment.

Le texte doit rester rendu par code.

## Billets / interaction

Conserver la logique actuelle :
- petit billet avec prix ;
- progression de maintien ;
- niveaux successifs.

Habillage :
- papier légèrement texturé ;
- contours cartoon ;
- segments N1/N2/N3 lisibles ;
- pas de gros menu.

## Institut / sondage

Le cercle électoral doit être :
- compact ;
- lisible ;
- cohérent avec les couleurs de faction ;
- pas un tableau complexe.

## Vignette de dégâts

Pas de barre de vie.

Créer par code ou asset transparent :
- vignette rouge sur les bords ;
- intensité progressive ;
- centre de l'écran clair.

## Polices

Réutiliser une police web/licenciée déjà présente si possible.
Sinon choisir une police système/ouverte facilement lisible.
Ne pas distribuer de fichiers de police propriétaires dans ce pack.
